# Crop Yield Lab

A machine learning project on crop yield and crop recommendation for agriculture, with an interactive
Streamlit app. Three modules use **real public data**; one is a clearly labelled **synthetic simulator**.

| # | Module | Data | Real? | Task |
|---|--------|------|-------|------|
| 1 | India yield | Kaggle *Crop Yield in Indian States* (19,689 rows, 30 states, 55 crops, 1997-2020) | Real | Regression |
| 2 | Crop recommendation | Kaggle *Crop Recommendation Dataset* (2,200 rows, 22 crops) | Public benchmark (see notes) | Classification |
| 3 | Global yield | FAOSTAT yields + World Bank climate (101 countries, 10 crops, 1990-2013) | Real | Regression |
| 4 | Field simulator | Generated by `src/simulator.py` | **Synthetic** | Regression |

## Module 1: India yield (real, Kaggle)

Inputs: state, crop, season, year, cropped area, annual rainfall, fertiliser and pesticide per hectare.

**Cleaning** (counts saved in `models/india_metrics.json`): coconut removed (recorded in nuts, not tonnes);
zero-yield rows, plots under 10 ha and extreme per-crop outliers removed (19,689 -> 18,833 rows). `Production` is
**not** used as an input because yield is production divided by area (it would leak the answer). Cotton, jute and
mesta are in bales/ha in the source. Rainfall, fertiliser and pesticide are identical for every crop in the same
state and year, so they are **state-level figures**, not field measurements. Rajasthan is not in the dataset.

**Method:** the model learns the *deviation* from the historical average yield of that state + crop + season
(computed leave-one-out for training rows). A plain model without this did not even beat that average.
Evaluation is by time: train 1997-2009, choose the model on 2010-2013, test on 2014-2020; the deployed model is fit
on 1997-2013.

| Test years 2014-2020 | R² | MAE (t/ha) | WAPE |
|---|---|---|---|
| Baseline (historical average of state-crop-season) | 0.913 | 1.06 | 23.6% |
| Ridge (chosen on validation) | 0.920 | 1.04 | 22.9% |
| Random Forest | 0.917 | 1.00 | 22.2% |
| Hist. Gradient Boosting | 0.917 | 1.03 | 22.8% |

For states never seen in training: R² 0.67, MAE 2.1 t/ha.
**Honest conclusion:** the model beats the simple historical average only slightly. State, crop and season explain
most of the yield; state-level rainfall, fertiliser and pesticide add very little.

## Module 2: Crop recommendation (Kaggle benchmark)

Inputs: soil N, P, K, pH, temperature, humidity, rainfall. Output: the most suitable crop with probabilities.
Best model (5-fold CV on the training split): Gaussian Naive Bayes, test accuracy 99.5% (Random Forest 99.3%,
KNN 98.0%, Logistic Regression 97.3%).

**Notes:** every crop has exactly 100 rows and the classes are almost perfectly separable (even Naive Bayes reaches
99.5%), which suggests the table was assembled or augmented, so treat it as a benchmark, not field measurements.
With noise added to the inputs (as a fraction of each input's spread) accuracy falls to 98% at 10%, 82% at 25% and
50% at 50%, so recommendations are only as good as the soil and weather readings.

## Module 3: Global yield (real, FAO)

Inputs: country, crop, year, rainfall, pesticides, temperature. Cleaning: 2,310 duplicate rows removed and
repeated temperature readings averaged to one row per country-crop-year (otherwise near-copies leak between train
and test). Time-based evaluation (train 1990-2003, choose 2004-2008, test 2009-2013).

| Test years 2009-2013 | R² | MAE (t/ha) |
|---|---|---|
| Baseline (country-crop mean) | 0.864 | 1.74 |
| **Random Forest (best)** | **0.915** | **1.30** |

For countries never seen in training: R² 0.62.

## Module 4: Field simulator (SYNTHETIC)

Real free datasets do not combine soil nutrients, irrigation and satellite NDVI with yields. `src/simulator.py`
therefore generates 6,000 synthetic fields from agronomy-style formulas (temperature and water optimum per crop,
diminishing returns to nitrogen, pH optimum) plus noise, so the inputs (soil N/P/K, pH, organic carbon, fertiliser,
irrigations, seed rate, NDVI, humidity, solar radiation, heat-stress days) can be explored. The model's high score
(R² about 0.97) only shows it learned those formulas, **not** how accurate it would be on real farms.

## Limitations

- Modules 1 and 3 are region-level (state or country) data, not field-level. No soil or satellite data are in them.
- All models learn **associations, not causes**; what-if curves should not be read as advice for one farm.
- Module 2's data look augmented; module 4 is synthetic by design.
- Data end in 2020 (India) and 2013 (FAO).

## Ideas for extension

- Real field-level data (soil tests, Sentinel-2 NDVI via Google Earth Engine, IMD weather) for true precision agriculture
- Live weather from a free API (e.g. Open-Meteo) to fill the weather inputs
- Prediction intervals (conformal prediction) and SHAP explanations
